# OrangeHRM Manual Test Points

## 1. 使用说明

本文档记录 Phase 1 第一版手工测试点，范围只包含三条核心业务链：

1. 登录、权限与退出；
2. 创建、查询和修改员工；
3. 员工申请请假、管理员处理、员工查看结果。

优先级说明：

- P0：核心流程失败会导致主要业务无法使用，优先执行；
- P1：重要异常、边界或数据一致性场景；
- P2：补充性的健壮性场景，有时间再执行。

表格中的“预期结果”是测试时用于判断是否通过的标准，不代表已经执行验证。业务规则没有实际确认时，会明确标记为“规则待确认”。

公共演示环境的数据可能被其他使用者修改或重置。执行时应使用容易识别且尽量唯一的测试数据，并记录执行时间和实际结果。

## 2. Login - 登录、权限与退出（10 条）

| ID | 优先级 | 测试点 | 预期结果 |
|---|---|---|---|
| LOGIN-01 | P0 | 输入正确用户名和正确密码登录 | 登录成功，进入 Dashboard，并显示当前账号有权访问的菜单 |
| LOGIN-02 | P0 | 输入正确用户名和错误密码 | 登录失败，停留在登录页并显示凭证错误提示，不进入内部页面 |
| LOGIN-03 | P0 | 输入不存在的用户名和任意密码，并与“用户名正确、密码错误”的提示进行比较 | 登录失败；记录两种场景的提示是否能够被用来判断账号存在，将账号枚举风险作为验证结论，不预设系统已经防护（规则待确认） |
| LOGIN-04 | P1 | 用户名为空、密码正确 | 不提交登录或登录失败，Username 显示必填提示 |
| LOGIN-05 | P1 | 用户名正确、密码为空 | 不提交登录或登录失败，Password 显示必填提示 |
| LOGIN-06 | P1 | 用户名和密码都为空 | 不进入系统，两个必填字段均得到明确提示 |
| LOGIN-07 | P1 | 正确用户名的前后加入空格 | 是否自动去除空格以及能否登录需要按实际结果记录（规则待确认） |
| LOGIN-08 | P1 | 改变正确密码中的字母大小写 | 记录大小写变化后能否登录，用于确认密码是否区分大小写（规则待确认） |
| LOGIN-09 | P2 | 用户名和密码输入超长字符串 | 页面不崩溃、不出现服务端异常且不能绕过登录；具体最大长度待确认 |
| LOGIN-10 | P0 | 登录后退出，再直接访问 Employee List 地址 | 退出后返回登录页；内部页面不能继续访问，并重定向至登录页 |

## 3. Add Employee - 创建员工（9 条）

前置条件：Admin 已登录，并进入 `PIM → Add Employee`。

| ID | 优先级 | 测试点 | 预期结果 |
|---|---|---|---|
| ADD-01 | P0 | 只填写 First Name、Last Name，使用系统默认 Employee Id 保存 | 员工创建成功并进入员工详情；详情中的姓名和 Employee Id 与输入一致 |
| ADD-02 | P1 | 填写 First Name、Middle Name、Last Name 和自定义 Employee Id 保存 | 员工创建成功，三个姓名字段和 Employee Id 均正确保存 |
| ADD-03 | P0 | 创建员工时打开 Create Login Details，填写唯一 Username、有效密码并设为 Enabled | 员工档案和登录账号同时创建；账号与该员工关联，实际能否登录需要后续验证 |
| ADD-04 | P0 | First Name 为空，只填写 Last Name 后保存 | 创建失败，First Name 显示必填提示，不产生员工记录 |
| ADD-05 | P0 | Last Name 为空，只填写 First Name 后保存 | 创建失败，Last Name 显示必填提示，不产生员工记录 |
| ADD-06 | P1 | First Name 和 Last Name 都为空后保存 | 创建失败，两个必填字段均显示提示，不产生员工记录 |
| ADD-07 | P1 | 使用已经存在的 Employee Id 创建员工 | 系统是否禁止重复、提示重复或允许保存需要按实际结果记录（规则待确认）；不得静默覆盖原员工 |
| ADD-08 | P2 | 姓名输入超长字符串后保存 | 页面应给出长度限制或稳定处理，不出现页面崩溃；各姓名字段最大长度待确认 |
| ADD-09 | P1 | 姓名包含连字符、撇号或中文，Employee Id 包含字母 | 分别记录系统的接受范围和提示（规则待确认）；如保存成功，详情与输入数据应一致 |

## 4. Search Employee - 查询员工（5 条）

前置条件：准备一条本轮新建、Employee Id 唯一且已记录姓名的员工数据。

| ID | 优先级 | 测试点 | 预期结果 |
|---|---|---|---|
| SEARCH-01 | P0 | 使用新建员工的完整 Employee Id 查询 | 结果中只展示匹配的员工，姓名和 Employee Id 与创建数据一致 |
| SEARCH-02 | P0 | 使用新建员工的 Employee Name 查询 | 结果中包含目标员工；姓名匹配规则是精确还是模糊需要按实际结果记录 |
| SEARCH-03 | P1 | 使用不存在的 Employee Id 查询 | 显示无记录，不出现其他无关员工数据或系统异常 |
| SEARCH-04 | P1 | 同时输入相互匹配的 Employee Name 和 Employee Id 查询 | 返回目标员工；多个查询条件共同生效 |
| SEARCH-05 | P1 | 输入查询条件后点击 Reset | 所有查询条件恢复默认值，可以重新进行查询 |

## 5. Edit Employee - 修改员工（5 条）

前置条件：使用本轮创建并能够稳定查询到的员工，先记录修改前数据。

| ID | 优先级 | 测试点 | 预期结果 |
|---|---|---|---|
| EDIT-01 | P0 | 修改员工 First Name 或 Last Name 并保存 | 页面提示保存成功；刷新详情后显示新姓名 |
| EDIT-02 | P0 | 修改 Employee Id 为新的唯一值并保存 | 页面提示保存成功；可以用新 Employee Id 查询到员工，旧 Employee Id 不再匹配该员工 |
| EDIT-03 | P1 | 清空 First Name 或 Last Name 后保存 | 保存失败并显示必填提示；刷新后原有有效数据没有被清空 |
| EDIT-04 | P1 | 将 Employee Id 修改为另一员工已使用的值 | 系统处理方式需要按实际结果记录（规则待确认）；不得导致原员工数据被静默覆盖 |
| EDIT-05 | P1 | 修改与当前登录员工关联的基础资料后，对比 PIM 与 My Info | 两个入口显示的数据应一致；ESS 是否允许修改相同字段需要后续用独立账号确认 |

## 6. Leave - 请假申请与处理（10 条）

完整流程需要准备一个可登录的 ESS 员工账号、有效假期类型和足够的假期余额。Admin 和 ESS 应使用不同账号验证各自权限。

| ID | 优先级 | 测试点 | 预期结果 |
|---|---|---|---|
| LEAVE-01 | P0 | 员工没有可用假期类型或余额时进入 Apply | 页面提示没有可用假期余额，员工不能直接提交申请；此现象已在当前演示账号观察到 |
| LEAVE-02 | P0 | ESS 选择有效假期类型和一个有效工作日提交请假 | 申请成功；员工可以在 My Leave 中看到该记录及初始状态 |
| LEAVE-03 | P1 | ESS 申请连续多个有效日期 | 申请成功；日期范围和请假天数计算正确，节假日/周末计算规则待确认 |
| LEAVE-04 | P1 | To Date 早于 From Date | 申请不能提交，并显示明确的日期范围提示 |
| LEAVE-05 | P1 | 申请天数超过当前可用余额 | 系统是阻止提交还是允许进入其他状态需要按实际结果记录（规则待确认）；余额不能被错误计算 |
| LEAVE-06 | P0 | ESS 提交申请后，Admin 按员工和日期在 Leave List 查询 | Admin 能查询到同一条申请，员工、日期、类型、天数和状态与申请一致 |
| LEAVE-07 | P0 | Admin 审批通过一条待处理申请 | 状态变为已批准；ESS 在 My Leave 看到相同状态；余额何时扣减需要记录确认 |
| LEAVE-08 | P0 | Admin 拒绝一条待处理申请 | 状态变为已拒绝；ESS 在 My Leave 看到相同状态；拒绝后余额处理正确 |
| LEAVE-09 | P0 | ESS 尝试访问管理员的请假审批功能 | 记录审批入口是否可见，以及直接访问审批地址时是否被拒绝或重定向，用于确认 ESS 的审批权限（规则待确认） |
| LEAVE-10 | P1 | 同一员工对相同或重叠日期重复提交请假 | 系统应给出明确处理，不应产生错误的重复扣减；是否允许重复申请待确认 |

## 7. 数量与执行顺序

当前共 39 条测试点：Login 10 条、Add Employee 9 条、Search Employee 5 条、Edit Employee 5 条、Leave 10 条。

建议执行顺序：

```text
Login P0
  ↓
Add Employee P0
  ↓
Search / Edit Employee P0
  ↓
准备 ESS 账号与假期余额
  ↓
Leave P0
  ↓
各模块 P1、P2
```
